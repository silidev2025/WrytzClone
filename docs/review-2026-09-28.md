### 1. iOS live tunnels expose a development server to the internet — High, unverified risk

`scripts/mobile/expo.mjs` starts `expo start --tunnel`, which publishes the Expo/Metro development server through ngrok. Development servers are not built for public exposure (source maps, `/symbolicate`, `/open-stack-frame`, the inspector proxy); CVE-2025-11953 is a recent example of a Metro endpoint that allowed command execution. The same machine keeps every app's Android signing keys (`~/.craftbase-mobile/keys`). The environment filtering is good, but it doesn't limit what a server flaw could reach.

Suggested correction: run the worker in an isolated VM or container that holds no signing keys or other secrets; keep Android signing on a separate machine; or replace the live tunnel with a static exported bundle (`expo export`) served read-only.

### 2. A failing phone-build clean-up stopped all retention clean-up — Medium, **fixed**

`runMaintenance` called `cleanMobileDeployments` first without catching errors, so any failure there skipped deleting expired sessions, invites, reset tokens, old audit entries and unsaved attachments: the retention periods promised on /privacy would silently stop. Now caught and logged (`src/lib/server/maintenance.ts`).

### 3. Habit streaks read every check-in on every query — Medium

`toRuntimeRecords` (`src/lib/server/data.ts`, streak recalculation block) loads all readable rows of the check-in collection for every query of a habits collection, including single-record queries; for an admin that is every user's history. Cost grows with total check-ins, per request. Suggested correction: compute only for the habits in the result, using rows filtered by the Habit field, or keep the recent dates on the habit record.

### 4. Privacy notice doesn't cover phone testing — Medium, needs a business decision

Phone testing sends app traffic through ngrok and Expo Go and keeps APKs for 7 days and signing keys indefinitely (handoff item 10). /privacy doesn't mention these providers, retention periods or that tunnel links are public. The operator must decide how they describe this and for how long keys are kept.

### 5. Publishing during an autosave failed with a misleading error — Low, **fixed**

`saveNow()` returned `false` while a save was in flight, so Publish reported "Your latest changes have not been saved". The new save path (`syncNow` in `src/components/editor/live.ts`) waits for pending saves instead.

### 6. Toasts shown during a modal can be hidden from screen readers — Low

`useModalFocus` makes every sibling of the modal inert. If a toast is already visible when a modal opens, its container becomes inert, and later toasts are added inside it: they are hidden from assistive technology and their action buttons can't be used. Suggested correction: exclude the toast region from inerting.

### 7. Habit time zone stored outside the record's data — Low

`checkInHabit` stores `habitTimeZone` as a top-level property of the record document. It isn't included in CSV exports or "download my data" and is dropped by some copies. Suggested correction: document it, or keep it with the record's data.

### 8. The device preview frame was blocked on plain http — Low, **fixed**

The CSP allowed only `https:` frames, so the preview (and the new device picker) was blocked on local http addresses. `'self'` added to `frame-src` (`next.config.ts`).
